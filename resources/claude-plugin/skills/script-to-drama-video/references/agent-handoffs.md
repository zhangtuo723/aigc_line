# 三个子 Agent 的报告与检查规范

主 Agent 调度和各子 Agent 执行时读取。报告必须写入当前项目磁盘，并在返回消息中给出绝对路径、结论与待处理项；下游必须读取文件和实际节点，不能只依赖返回消息。报告中的节点 ID、字段和路径必须来自工具读取结果，不能虚构。报告修订号只用于文件交接，不是 Canvas 版本号，不传给画布写工具。

## 共同输入

每次交接明确项目目录、原始剧本文件路径、本次任务报告目录、创作参数、用户授权范围及本轮处理的节点 ID。标明源剧本的内容摘要/版本依据（例如内容哈希）、报告修订号和更新时间，避免检查不同版本。长剧本应分段读完并记录覆盖章节/场次；文件不可读或正文不全时报告缺口，不推测为已读。

报告只约束本次任务范围；总览中列出画布已有的其他资产及“未纳入本次制作”状态，避免误称它们不存在或误用其他任务素材。资产生成、视频编辑和检查按阶段串行；用户在检查期间修改节点时，重新读取变化范围，不能用旧报告覆盖用户修改。

## 资产 Agent → 资产报告.md

直接读取剧本，按主 Skill 的资产规则生成或复用人物、场景、关键道具；图片生成确认仍由主 Agent 取得。完成图片检查后，使用 GetCanvasOverview 查实际资产节点，再用 GetCanvasNode 核对纳入任务的资产详情。报告包含：

1. **来源与范围**：剧本路径和版本依据、覆盖场次、统一风格/画幅、报告修订号。
2. **画布资产清单**：每项列出资产类别、名称、真实 nodeId、工作流、实际 generationStatus、sourcePath、是否本次使用及可用/待生成/失败/未核实状态。其他任务资产可单列简表，不得冒充本次已验证资产。
3. **人物映射**：characterId、身份底图 nodeId、outfitId、服装/妆造/状态、适用场次/sceneId、实际派生图 nodeId、底图→派生图连接；复用底图的版本也明确列出。记录检查过的身份一致性。
4. **场景与道具映射**：sceneId、地点、时间天气/光源、空间布局/出入口、版本差异、nodeId；关键道具的外观、使用者与出现范围。已有音视频参考也记录实际用途和路径。
5. **缺口与交接结论**：缺少或失败资产、待确认事项、是否“交接就绪”。只有必需资产都有有效输出、已核实且图像检查合格，才能就绪；idle 不代表生成成功。

分镜师要求补资产时，资产 Agent 更新同一报告、递增修订号并列出新增/重做/复用项目。底图重做导致派生图失效时，先完成派生图重做；素材路径未变但内容已换也必须告知下游重查。

## 分镜师 Agent → 分镜交接.md

直接读取原剧本与最新资产报告，核对所用资产的实际节点。分镜交接是审查依据，最终 prompt 仍须完整写入 video 节点。包含：

- 源剧本与资产报告的版本依据、规划修订号、改编说明、覆盖场次与原台词/关键事件的对应关系。
- 按播放顺序列出全部 SEG 编号、真实 video nodeId、目的、5/10/15 秒时长、画幅、工作流、完整导演包及片内 Shot 连续时间线。
- 每片三类 reference 数组的真实顺序；逐槽位列 nodeId、sourcePath、人物身份/服装或场景版本、用途与最终 prompt 引用标签；没有音视频引用时明确为空。列出实际入边，不能用连线视觉顺序代替数组顺序。
- 每片开场/结束连续性账本，以及相邻片段的具体承接方式。
- 已写入节点的最终 H3 prompt 原文与关键生成字段快照，供检查员与实时画布对照；所有字段以实际读取为准。
- 复修时按检查问题 ID 列出修复内容、受影响节点和相邻衔接、仍未解决事项；更新整份交接，不能只追加“已修复”。

## 检查 Agent → 检查报告-第NN轮.md

检查 Agent 必须独立读取原剧本、最新资产报告和分镜交接，再用 GetCanvasNode 逐一读取本次全部视频和所引用素材。只读画布，禁止修改节点或生成。检查 H3 时读取 `aigc-canvas:h3-prompt-writing` 的实际 Skill 及其 Ref2VA 规范，按真实数组验证，不能凭记忆猜格式；工具或文件不可访问时结论为阻塞。

逐项检查：

| 维度 | 判据 |
|---|---|
| 剧本覆盖 | 关键人物关系、事件、因果、结局和必须保留的台词有对应片段；增补不擅改核心剧情 |
| 人物与资产 | nodeId 对应正确角色、服装/妆造/状态和场景；素材真实可用；需要时读取实际图片验证，不能只凭标题 |
| 引用与连线 | 数组槽位、prompt 标签、素材用途和真实入边一致；无缺失节点、错序、超限或错误的首尾帧字段 |
| 分段与时间 | 每片 5/10/15 秒；内部 Shot 从 0 连续覆盖全时长，无空洞/重叠；对白、动作、停顿与反应有足够预算 |
| 连续性 | 相邻片段人物站位/朝向/服装、轴线、视线、动作阶段、道具数量/持有人/左右手、场景光源与声音承接明确 |
| 补镜与描述 | 观众能理解进入、行动、关键反应和转折；必要时补建立镜头、反应或细节，但每个新增 Shot 都要有叙事理由与时间预算，禁止机械加镜 |
| H3 prompt | 按官方 Skill 验证 Ref2VA 结构、引用标签、时间戳、说话者、口型、对白/旁白和声音字段；导演包要点未丢失，默认无 BGM |
| 交接一致性 | 实际节点 prompt、时长、画幅、工作流、引用数组、素材输出和入边与当前交接一致；检查范围覆盖全部待生成节点 |

每轮报告必须包含：

1. **检查依据**：轮次、时间、原剧本和两份交接的版本依据、全部被检查节点 ID。
2. **逐片结论与跨片衔接**：每片及每对相邻片段的通过/未通过/阻塞和证据；记录当前实际 prompt、生成字段、引用映射及素材输出依据，可使用完整快照或内容摘要/哈希绑定内容，不只记录标题。
3. **问题清单**：稳定的问题 ID、严重性（必须修复/可选建议）、SEG/nodeId、具体字段/Shot 时间或原剧本位置、观察到的问题、修复要求及复查判据。关键反应缺失、信息不清等影响理解的问题必须修复；纯审美偏好可作为可选建议。
4. **历史问题复查**：逐项注明已验证修复/仍存在/引入新问题及实际证据。不得把分镜师的处理说明当作验证结果。
5. **最终结论**：明确写“通过”“未通过”或“阻塞”，列待生成节点集合。只有全部必查项完成、全部必须修复问题关闭、当前节点与交接一致才能通过；可选建议说明不阻止通过的理由。

保留每轮报告，另更新 `检查报告.md` 指向最新轮次并写明当前结论。主 Agent 读取最新报告，核对当前节点与通过快照；发生变化则退回复查，不生成变化后的未审内容。局部修复复查可以聚焦改动和相邻衔接，但报告必须明确哪些未变节点沿用哪一轮有效结论，保证最终生成集合全部受有效检查覆盖。
