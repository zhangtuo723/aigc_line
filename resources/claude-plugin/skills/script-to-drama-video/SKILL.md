# 剧本转 AI 短剧

把输入深化为可生成、可衔接的视频片段。画布只承载生产资产：人物/场景/道具 `image`、片段 `video`、必要的 `audio` 与放大节点。不要创建 `text` / `shot` 节点、分镜表或 `.storyboard.json`；剧情规划、旁白和时间线直接写入对应 image/video 的 prompt。资产报告、分镜交接和检查报告是项目内 Markdown 文件，用于子 Agent 交接和复查，不是画布文本节点或分镜表 artifact。

规划新作品、重做片段结构或修复连续性前，读取 [references/directing-and-continuity.md](references/directing-and-continuity.md)。简单修改用户明确指定的现有节点时，只处理请求范围，可复用已核实的资产报告，不强制重建资产；若改动视频 prompt、引用或片段结构，仍须由分镜师修改、检查 Agent 复查通过后才允许生成。

严格区分：

- **生成片段**：一次独立 H3 生成，对应一个 `video` 节点，时长只能为 5/10/15 秒。
- **片段内 Shot**：同一视频内部按时间发生的真正镜头，可有一个或多个，只写入导演包和最终 H3 prompt，不创建 Canvas 节点。

## 总流程

```text
主 Agent 接收剧本文件、确认创作参数与授权范围
→ 资产 Agent 读取原剧本 → 建立并生成/复用人物、场景、道具资产 → 资产报告.md
→ 分镜师 Agent 读取原剧本 + 资产报告 → 拆片段/内部 Shot → 创建节点与连线
  → 逐片段调用 h3-prompt-writing 写入 prompt → 分镜交接.md
→ 检查 Agent 读取原剧本 + 报告 + 实际画布 → 检查报告-第NN轮.md
  ├─ 未通过 → 分镜师优化（缺资产则先退回资产 Agent 补齐报告）→ 检查 Agent 复查
  └─ 通过 → 主 Agent 核对通过范围与当前节点、确认生成授权 → 生成视频 → 核对产物 → 交付
```

## 三个子 Agent 的职责与交接

主 Agent 必须使用当前运行环境实际提供的子 Agent 委派能力，创建三个职责独立的子 Agent；不能在同一上下文中自称三个角色来代替真实委派。按依赖串行执行，可恢复同一角色的子 Agent 进行补充和复查，禁止分镜师自审自批。专项 Skill 是角色内部调用的方法，不替代这三个子 Agent。若子 Agent 无法直接调用专项 Skill，可读取该 Skill 执行；仍不得自行仿写其模板。若运行环境缺少委派或必要工具，应明确报告阻塞，不能声称已经完成子 Agent 检查或继续生成。

主 Agent 调度前，以及每个子 Agent 开始工作时，读取 [references/agent-handoffs.md](references/agent-handoffs.md)，按其中要求写入并实际读取交接文件。给每个子 Agent 传入项目目录、原始剧本文件绝对路径、创作参数、当前报告目录、精确节点范围、已有授权和本 Skill 路径；不要只传上一个 Agent 的自然语言摘要。报告统一存入项目 `generated/drama-reports/<本次任务标识>/`，续作复用该目录，不覆盖其他任务的报告。

- **主 Agent**：负责用户沟通、授权、串行调度、报告验收和最终视频生成。子 Agent 需要确认时回报主 Agent，由主 Agent 向用户询问并取得答复后恢复任务；不能把启动子 Agent 当作生成授权。
- **资产 Agent**：直接读取完整剧本，执行第 3–4 节，调用人物/场景 Skill，生成或核实并复用资产，读取实际节点与图片后输出 `资产报告.md`。只负责资产，不创建视频或触发视频生成。
- **分镜师 Agent**：同时读取完整剧本和最新资产报告，执行第 2、5–7 节，深化节拍、拆分片段、建立连续性账本、创建/更新 video 与连线、逐个生成最终 H3 prompt，输出 `分镜交接.md`；不能触发视频生成。需要新资产时向主 Agent 提交明确需求，由资产 Agent 补齐后继续。
- **检查 Agent**：独立读取原剧本、最新资产报告、分镜交接和全部本次 video 节点及引用资产，按交接规范检查人物引用、片段合理性与连贯性、必要补镜/描述和 H3 格式；每轮输出检查报告。只读画布，只写检查报告，不代替分镜师修正节点，也不触发生成。

第 1 节由主 Agent 执行，第 8 节由主 Agent 在检查通过且已有生成授权后执行。以下创作与画布规范由相应角色遵守。

## 1. 确认创作参数

用户提供剧本文件时，各角色都必须读取该文件正文，不得把文件名、聊天摘要或资产报告代替原剧本。纯文本/梗概输入先由主 Agent 原样保存为报告目录中的 `原始输入.md`，作为共同源文件，扩写另行标明。先判断输入是否完整。只有用户要求忠实改编却缺少关键正文时才索取材料；用户明确只给梗概或创意时，可在不违背核心设定的前提下扩写。

一次性确认：

- 画幅：`16:9`、`9:16`、`1:1` 或 `4:3`；
- 统一视觉风格、时代、地域、色彩和材质；
- 改编强度：默认忠于核心、艺术化表达；逐字逐场还原必须由用户明确要求；
- 台词/旁白语言、角色声线；默认无 BGM，只保留台词、旁白、环境音和拟音；
- 5/10/15 秒时长策略。不能把超量对白和动作硬塞进 15 秒。

## 2. 深化剧本

默认保留核心人物关系、关键事实、主要冲突、因果、决定性事件和结局方向。可以：

- 重排信息揭示顺序，增加悬念、伏笔、对照、动作匹配和声画桥；
- 把心理与说明转成可见动作、表情、停顿、视线、空间调度、道具和声音；
- 补写不改变人物意图的对白、反应、潜台词或旁白；
- 合并重复信息，补足进入、承接、升级、转折和收束节拍。

改变核心动机、关键事件、人物关系或结局前必须确认。严格还原模式下保留原台词、事件顺序和场次边界，只补足拍摄所需的动作、机位、声音和时间分配。

逐场建立“目标 → 阻力 → 行动 → 反应 → 信息变化 → 情绪转折 → 离场钩子”，先确定人物和道具在空间中的起点、路径、视线、遮挡与结束位置，再选择机位和运镜。记录：

- 场景目的、开场钩子、高潮落点与下一场声画桥；
- 角色进入状态、欲望、策略和场末变化；
- 必须保留的事实/原句与允许改写的部分；
- 可视化动作、关键反应、道具、环境和声音母题；
- 每句对白、画外对白、内心独白和旁白的说话者与剧情位置。
- 每场的轴线、人物左右关系、出入口、动作手和关键道具状态。

向用户展示改编策略和主要增补、合并或重排。只有触及核心剧情时才等待额外批准。

## 3. 建立资产清单

为每个角色分配稳定 `characterId`，记录年龄段、体型、肤色、脸型、五官、发型、识别特征、气质和姿态习惯。

每个 `characterId` 指定一个基准外观作为唯一身份底图。再按“角色 × 剧情阶段/服装/可见状态”建立 `outfitId`，并绑定使用它的 `sceneId`；只有颜色、材质、版型、鞋帽、饰品、妆造、破损、湿润或沾污等确实变化时才新建版本。外观完全相同的多个场景必须复用同一版本。

为每个不同地点或明显变化的环境建立 `sceneId`，记录空间布局、材质、固定家具、出入口、时间、天气、主光方向、色温和氛围。同一地点的昼夜、天气、灯光或破坏程度明显变化时建立新版本。

关键道具只有在跨场保持外观、被角色持有或需要特写辨识时才创建独立 `image` 参考节点。普通固定物件直接进入场景参考图。

## 4. 委派参考图

人物和场景生成不得在本 Skill 内复制模板。

### 人物

调用 `aigc-canvas:character-reference-generation`，传入完整角色身份档案、基准外观、每个 `outfitId` 与场景绑定关系和统一视觉风格。必须形成两层人物资产图：

- 每个角色只有一个文生图身份底图，单张横向 16:9 四联，从左到右为头部近景、自然站立全身正面、侧面、背面；
- 不同场景的服装、妆造或状态版本必须以该身份底图为唯一参考，通过 `身份底图 → 场景派生图` 连线触发图生图；
- 所有派生分支直接连接身份底图，禁止用一个变体继续派生另一个变体；
- 外观与底图相同的场景直接复用底图，外观相同的多个场景复用同一派生图；
- 底图与派生图的三个全身角度都不使用 A-pose 或 T-pose。

### 场景

调用 `aigc-canvas:environment-reference-generation`，传入每个 `sceneId`、空间档案、视觉风格和成片画幅。每个场景版本应得到一个无人 `image` 节点：

- 高机位俯视全景，完整交代空间、出入口、行动路线、家具与关键道具；
- 保留真实透视、立面、材质和纵深；
- 不生成普通平视环境图、二维户型图或多视图拼贴。

参考图分阶段生成，不能一次并发触发全部人物节点：

1. 汇总角色身份底图和环境图的节点、工作流与中文提示词摘要，询问是否开始生成第一阶段参考图；确认后生成并等待全部完成。
2. 读取并确认每个角色底图已有有效 `sourcePath` 后，创建/核对人物场景派生节点及 `身份底图 → 派生图` 连线；汇总底图映射、场景/服装版本和图生图工作流，重新询问是否开始生成派生人物图。
3. 只有第二次明确确认后才能调用派生节点的 `InvokeNodeAction(generate)`。不得让缺少底图输出的派生节点退化为独立文生图。

读取实际图片并检查底图四联的顺序、身份辨识度、全身角度完整性和自然站姿；逐个对照底图检查派生图是否同脸、同年龄、同体型、同肤色、同发型，只改变指定服装/妆造/状态；检查环境图是否确为无人俯视全景、空间可读、布局与光线正确。不合格时说明原因、修正对应节点，并在重做前重新取得确认。底图重做后，其全部派生图必须重新生成和复核。

完成后由资产 Agent 按交接规范写出 `资产报告.md`；只有本次分镜所需资产全部可用、报告明确交接就绪，才能启动分镜师。未生成、失败或待确认资产不得标为可用。

## 5. 规划生成片段

参考图合格后，把深化剧本拆成可独立生成的 5/10/15 秒片段。每个片段围绕一个明确节拍，包含开场状态、动作推进、人物反应、信息/情绪变化和结尾落点；必须能说明“观众在片段结尾比开头多知道、感到或期待什么”。

当剧情目标或人物状态显著改变、地点/时间改变、对白与动作超出预算，或图片引用超过 9 张时拆片。中文自然对白按约 3–5 字/秒估算，同时为停顿、反应、动作和切镜留时间。

为每个片段设计连续覆盖完整时长的内部 Shot：

- 使用 `SEGxx-yy` 编号；
- 第一段从 0 秒开始，后段起点等于前段终点，末段结束时间等于片段时长；
- 明确景别、机位、构图、人物位置、动作过程、表情/视线、运镜、声音和切出依据；
- 默认优先一个可执行的连续 Shot；只有引入新信息、关键反应、新空间关系、新状态、新时间或当前构图无法清楚表现下一动作时才切镜；
- 每次切镜写明新增信息和切出依据，不为追求节奏机械增加镜头；
- 保持轴线、视线、人物左右位置、动作、道具、光源和声音连续；
- 片段间明确动作承接、视线匹配、声音桥、构图呼应或光色衔接，不能只写“自然转场”。

同时建立连续性账本，记录每个片段开场与结束时的人物身份/服装/站位、道具数量/持有人/所在手、sceneId/光源、动作阶段、轴线和声音状态。后一个片段的开场必须显式继承或解释变化。

向用户展示片段规划和内部 Shot 时间线。每个片段至少列出目的、时长、开场、动作/反应、台词/旁白、声音、结尾和衔接。

## 6. 创建视频节点与引用

每个生成片段直接创建一个 `video` 节点，不创建配套 `shot` 节点：

- 标题包含连续片段序号，例如 `SEG02｜客厅质问`；
- `workflowId` 固定为 `minimax-h3-r2v`；
- `duration` 为 5、10 或 15；
- `aspectRatio` 与成片一致；
- `referenceImageNodeIds` 最多 9 个，顺序为本片段出场人物的当前场景四联图（按首次出场/对白顺序；无派生版本时使用身份底图）→ 当前环境俯视全景图 → 必需关键道具；
- 只有实际使用的服装和场景版本进入数组；
- 从所有引用 image 节点连接到 video 节点；
- 不设置 `firstFrameNodeId` / `lastFrameNodeId`。

剧情规划、旁白、时间线和最终生成要求必须完整写入对应 video prompt，不创建额外文本节点。不同片段纵向排列，参考资产放在左侧或上方。

## 7. 委派 H3 提示词

为每个 video 整理导演包：

- 目标时长、画幅、媒介风格、色彩、光线、表演尺度；
- 片段目的、开场构图、人物位置、动作路径、表情/视线、道具状态、结束构图；
- 内部 Shot 时间线、切点、每次切镜的新信息、切出依据和运镜；
- 完整台词/旁白、说话者、声线、情绪、语速、口型与沉默角色反应；
- 环境声、同步拟音、非语言人声和无 BGM 要求；
- 本片段开场/结束连续性状态，以及与相邻片段的动作、视线、构图、光色或声音衔接；
- 三类 reference 数组的真实顺序和每个素材用途。

逐片段调用 `aigc-canvas:h3-prompt-writing`，明确使用 full-reference Ref2VA。不得自行仿写或维护 H3 官方模板。由该 Skill 生成并校验引用标签、结构、时间戳、对白和声音字段。

写入 video 的 `prompt` 前核对：

- 引用编号与真实数组槽位完全一致，失败素材不得过滤后重新编号；
- 切点严格落在时长内，动作和对白有可执行预算；
- 原语言、说话者、口型和旁白规则正确；
- prompt 保留片段目的、表演、内部 Shot 与片段间衔接；
- 输出符合 `h3-prompt-writing` 的格式。

写入后重新读取实际节点，输出 `分镜交接.md`，包含全部视频节点的片段摘要、导演包/内部 Shot、引用映射、连续性账本、声音与改编说明。交给独立检查 Agent，不能在分镜师完成后直接生成视频。

### 检查、优化与复查门

检查 Agent 按 `references/agent-handoffs.md` 逐片核对并检查相邻片段，输出带问题 ID、证据、修复要求和明确结论的轮次报告。任何人物/服装/场景误用、缺失素材、引用编号错误、关键剧情遗漏、时间超载、无依据跳变、必要镜头/描述缺失或 H3 格式不合规都不得通过。

主 Agent 将未通过报告交回分镜师，分镜师逐项修改导演包、节点、引用/连线，并重新调用 H3 Skill 更新受影响 prompt；缺资产时先由资产 Agent 补齐并更新资产报告。分镜师更新交接文件，标明每个问题的处理结果，再交检查 Agent 重新读取实际画布验证；不得仅凭“已修复”说明关闭问题。重复检查→优化→复查，直到本次待生成范围全部通过。

不存在“达到轮数自动通过”。工具故障、必需素材缺失、待用户决策或连续两轮同一阻塞无进展时，保存未通过报告、说明阻塞并等待解决，禁止盲目循环或绕过检查生成。条件补齐后继续同一闭环。

通过结论只对报告记录的剧本、资产和实际节点内容有效。通过后任何 prompt、时长、工作流、画幅、引用顺序、素材输出或连线变化，均使受影响片段及其相邻衔接的通过结论失效，必须复查；当前待生成集合必须全部被有效通过结论覆盖。

主 Agent 展示最终检查报告与待生成片段摘要。只有检查通过且用户明确同意生成后，才能触发 video 的生成动作；会话内已有覆盖当前范围的明确授权时沿用，范围改变时取得对应授权。检查通过本身不是用户授权。

## 8. 产物核对与交付

等待所有 video 节点离开 `generating`，逐个读取节点并确认 `generationStatus`、`sourcePath` 与片段编号对应。生成失败时报告具体节点和错误；不要把“已有文件路径”等同于质量审核结论，也不要自动调用通用视频分析。

若用户明确要求分析某个生成视频，再把对应 `sourcePath` 和用户的具体问题交给 `AnalyzeVideo`。它是自由任务的视频分析工具，不负责自动判定通过、重做或跨片连续性。

用户需要剪映草稿时调用 `aigc-canvas:jianying-draft`，按 video 标题中的片段序号排列。交付时列出人物资产、场景资产、生成片段数、内部 Shot 数、失败情况和最终路径。

## 画布规范

- 用 `GetCanvasOverview` 查规模和 ID，用 `GetCanvasNode` 读具体节点，用 `GetCanvasCapabilities` 核对字段和动作。
- 优先批量创建、更新和连接；写入采用最后写入者生效，不传版本号。
- 只写能力表声明的字段。生成完成顺序不等于片段顺序，始终按节点 ID、标题、引用数组和 `sourcePath` 对齐。
- 保留用户明确引用或要求修改的节点 ID；不要为了方便整批重建。
