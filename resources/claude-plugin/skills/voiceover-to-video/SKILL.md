# 旁白配视频

把中文旁白音频和 SRT 字幕制作成分镜化 AIGC 短剧。始终以 SRT 时间轴为准：分镜时长必须对齐旁白，不要按情绪节奏自由改变总时长。

## 输入要求

- 旁白音频：最终使用的 `.mp3` 或 `.wav`，合成时保持原速。
- 字幕：与音频逐句对齐的 `.srt`，作为拆镜、对时和最终字幕的唯一依据。

缺少任一文件时先向用户索取，不要开始生成。

## 开始前确认

一次性向用户确认：

1. 画幅比例：`16:9`、`1:1` 或 `4:3`，图片和视频必须一致。
2. 视觉风格：用于所有图片提示词的统一风格描述。
3. 视频时长档位：只使用 `5/10/15` 秒，默认让每镜旁白接近 5 秒，必要时合并到 10 或 15 秒。
4. 对齐方式：默认逐镜变速，使每个视频精确覆盖对应 SRT 时间段；旁白保持原速。
5. 主角一致性：是否要求全片使用同一主角形象；未指定时只保证整体视觉风格一致。

这里的参数确认不等于授权生成。不得在开始前一次性预先取得图片和视频的生成授权；必须在对应阶段准备完成后单独询问。

## 强制生成授权门

- **图片生成门**：先完成分镜、shot/image 节点和全部中文图片提示词，把待生成的镜头数、工作流、画幅和提示词摘要展示给用户，然后明确询问“是否开始生成图片？”。只有用户明确肯定后，才能调用任何图片节点的 `generate`。
- **视频生成门**：所有图片经独立子 Agent 审核合格、视频提示词准备完成后，把待生成的视频数、工作流、时长档位和提示词摘要展示给用户，然后明确询问“是否开始生成视频？”。只有用户明确肯定后，才能调用任何视频节点的 `generate`。
- 用户的沉默、含糊回复、开始前的参数确认或较早回合中的笼统授权，都不能视为当前生成阶段的确认。询问后停止执行并等待用户回复，不得一边询问一边开始生成。
- 重新生成失败或不合格的图片/视频也属于生成。先说明重做原因、节点范围和修改内容，再重新取得用户明确确认。
- 创建或修改节点、提示词和连线不属于生成，可以在授权前完成；`InvokeNodeAction(generate)` 及任何会实际触发 ComfyUI 生成的操作必须受上述授权门约束。

## 强制独立审核

- 所有带有“检查、审核、验证、验收、确认合格”含义的工作，必须新启动一个独立子 Agent 执行。生产主 Agent 不得自行判定合格，也不得用普通自检替代子 Agent。
- 每个审核轮次都启动新的审核子 Agent；修复或重做后必须再启动新的独立子 Agent 复审，不能沿用原审核结论。
- 审核子 Agent 只负责读取原始依据和输出结构化审核报告，不生成、不改节点、不修文件。向它提供必要的 SRT、节点数据、实际媒体路径和验收标准，但不要暗示期望结论。
- 审核报告必须逐项给出 `pass/fail`、证据、问题节点 ID 和修改建议。生产主 Agent 根据报告修正；只有最新一轮报告全部通过，才能进入下一阶段或宣布完成。
- 至少分别执行：分镜与时间参数审核、生成图片审核、生成视频与最终时间线验收。任何额外审核也遵守同一规则。
- 若当前运行环境无法启动子 Agent，立即停止对应审核和后续流程，明确告知用户这一阻塞；不得降级为主 Agent 自审。

## 严格执行顺序

```text
解析 SRT → 拆分时间段 → 独立子 Agent 审核分镜与时间参数
→ 创建 shot/image 节点并编写中文图片提示词
→ 询问并等待图片生成授权 → 生成图片 → 独立子 Agent 审核图片，不合格则经再次授权后重做
→ 根据已审核实图编写中文视频提示词 → 创建 video
→ 询问并等待视频生成授权 → 生成 video → 独立子 Agent 审核视频
→ 逐段变速对齐 → 使用 jianying-draft 合成视频、原速旁白和原 SRT → 独立子 Agent 最终验收
```

### 1. 解析 SRT 并拆分镜头

使用 Python 解析 SRT，得到每句字幕的开始时间、结束时间和文本，然后贪心累积：

- 每镜旁白跨度尽量接近 5 秒，必要时合并到 10 或 15 秒档位。
- 把过短的结尾段合并回前一镜，避免极端变速。
- 对每镜记录：镜头号、开始时间、结束时间、合并台词、旁白跨度 `narrationDuration`、视频槽位 `slotDuration`。
- 计算播放速度 `speed = slotDuration / narrationDuration`。优先让速度落在 `0.9–1.6`；超出时重新调整分段。
- 时间段必须连续覆盖到 SRT 最后一句的结束时间；保留字幕间的停顿，不要让累计时长漂移。

拆分完成后启动独立子 Agent，审核时间段覆盖、槽位选择、速度范围和台词归属。审核通过后才继续；未通过则修正并启动新的子 Agent 复审。

### 2. 创建 shot 节点

先调用 `GetCanvasOverview` 获取画布的节点数量和轻量摘要。为每镜创建一个 `shot` 节点，只写当前能力表支持的字段：

- `shotNumber`：镜头号。
- `scene`：用紧凑的结构化文本保存时间信息和内容，例如：

```text
00:00.000→00:05.200｜旁白 5.2s｜槽位 5s｜速度 0.962｜台词：……｜画面：……
```

不要向 shot 写入 `dialogue`、`camera` 或 `duration`；这些字段当前不受支持，会被丢弃。镜头纵向排列。

### 3. 创建并生成图片

- 每镜创建一个 `image` 节点。
- `prompt` 必须使用中文，包含用户确认的风格、主体、动作、环境、构图、光线和摄影语言。除工作流强制要求的专有名词、模型标记或参数外，不得把系统实际使用的图片提示词翻译成英文。
- 设置统一的 `aspectRatio`。
- 先调用 `GetCanvasCapabilities` 获取当前可用的图片 `workflowId`，不要猜工作流 ID。
- 批量创建 image 节点并连接 `shot → image`。向用户展示生成摘要并询问“是否开始生成图片？”，等待用户明确确认后，才可通过 `InvokeNodeAction(generate)` 生成。

### 4. 检查图片，不可跳过

等待各图片节点的 `generationStatus` 结束，然后启动新的独立子 Agent，要求它读取 `sourcePath` 对应图片并逐张检查：

- 内容是否符合该镜台词和画面主题；
- 风格、画幅是否正确；
- 用户要求主角一致时，人物外观、服装和关键特征是否连续。

生产主 Agent 根据审核报告修改不合格 image 的中文提示词，向用户说明重做范围并再次询问是否开始生成这些图片。取得明确确认后重新生成，再启动新的独立子 Agent 复审，直到全部合格。绝对不要在图片生成并经独立审核通过前编写视频提示词。

### 5. 根据实图编写视频提示词

先查看每张最终图片中的真实人物、道具、环境、构图和光影，再为**一个 video 节点编写一条包含多个连续子分镜的中文提示词**。不要只写一段笼统动作描述。子分镜是在同一个 `5/10/15` 秒视频槽位内发生的镜头变化，不是新增 Canvas shot 节点。

#### 视频提示词硬性要求

- 开头先定义整段统一的视觉风格、时代与空间、色彩、光影、质感、人物连续性、总体情绪和节奏曲线，再写分时子分镜。
- 每条提示词必须包含至少 2 个子分镜。建议密度：5 秒写 2–3 个，10 秒写 3–5 个，15 秒写 4–7 个；动作复杂时宁可减少切换，保证每个动作可看清。
- 每个子分镜必须使用精确且连续的时间区间，例如 `0–2s 镜头1`、`2–5s 镜头2`。第一段从 `0s` 开始，后一段起点等于前一段终点，最后一段结束时间等于节点 `duration`，不得重叠、留空或超时。
- 每个子分镜都要说明：景别、机位/视角、主体与空间关系、可见动作、表情或物体状态变化、运镜方式、光影或环境变化、该段音效，以及如何进入下一镜。
- 明确镜头切换与变化：硬切、动作匹配剪辑、视线匹配、遮挡转场、甩镜转场、推近接特写、拉远揭示环境、焦点转移或同镜连续运镜。不要只写“镜头切换”；写清切换触发点、方向和切换后的构图变化。
- 相邻子分镜必须保持人物身份、脸型、发型、服装、道具、左右位置、场景结构、时间天气和光源方向连续。除非剧情明确要求，禁止人物变脸、服装突变、物体凭空出现/消失、空间跳变。
- 只驱动实图已经存在或可由其自然推导的元素。允许通过推拉摇移、轻微转身、局部特写、前后景遮挡和焦点变化丰富镜头；不得凭空增加主要人物、关键道具或全新地点。
- 动作必须可执行并有过程：写清起始姿态、动作路径、速度、受力/惯性、结束状态和细微反应，避免同一时间堆叠互相冲突的动作。
- 禁止生成任何 BGM、配乐、旋律或歌曲。允许生成与画面同步的环境音、拟音和动作音效，例如风声、雨声、脚步、衣料摩擦、门轴、车辆、器物碰撞；按子分镜标注触发时间、远近、强弱和空间方位。
- 为给原速旁白留出清晰空间，默认禁止新增对白、旁白、吟唱和不可辨识人声；音效保持克制，不得持续轰鸣或盖过旁白。剧情确需人物出声时，先向用户确认。
- 把所有运镜、子分镜、转场和音效要求写进 video 的 `prompt`，不要写进 shot。

#### 标准模板

按以下结构生成，尖括号内容全部替换为具体描述，不要原样保留占位符：

```text
【全局设定】
时长：<5/10/15秒>；画幅：<比例>。
统一风格：<媒介/类型、时代、写实或动画程度、镜头语言参考>。
色彩与光影：<主色、对比度、光源方向、明暗变化、景深、颗粒/质感>。
场景连续性：<地点、时间、天气、空间结构、前中后景固定元素>。
主体连续性：<人物外观、发型、服装、道具、初始位置与朝向；全程不得改变的特征>。
总体节奏：<由慢到快/压抑后释放等>；情绪曲线：<起点→变化→终点>。
声音总则：禁止 BGM、配乐、旋律和歌曲；禁止新增对白与旁白；只生成克制、真实、与动作同步的环境音和拟音，不得遮盖原旁白。

【分时子分镜】
0–<n>s 镜头1：<景别>，<机位/视角>。<主体起始状态和构图>；<分步骤动作、表情、环境反应>。运镜：<方向、速度、路径、焦点对象、结束构图>。光影变化：<具体变化>。音效：<时间点、声音来源、远近/左右方位、强弱>。镜尾通过<动作/视线/遮挡/甩镜等明确触发点>切换到下一镜。
<n>–<m>s 镜头2：<切换方式及与上一镜的匹配关系>；<新的景别、机位和构图变化>。<主体连续动作与结束状态>。运镜：<具体要求>。光影变化：<具体变化>。音效：<具体同步音效>。镜尾<如何过渡>。
<m>–<总时长>s 镜头N：<承接关系>；<收束画面、动作落点和最终构图>。运镜：<具体要求>。光影变化：<具体变化>。音效：<具体同步音效及自然衰减>。最后定格/停留在<便于剪辑衔接的稳定状态>。

【负面约束】
禁止 BGM、配乐、歌曲、旋律、新增对白、新增旁白；禁止字幕、水印、Logo；禁止人物变脸、五官漂移、肢体畸形、手指异常、服装突变、道具增减、场景跳变、光源跳变；禁止无动机乱切、瞬移、动作跳帧、镜头抖动、运镜方向冲突；禁止新增实图中不存在的主要人物、关键道具或地点。
```

#### 15 秒示例骨架

以下仅示范时间结构和镜头变化密度；实际内容必须根据最终实图与旁白重写：

```text
【全局设定】统一电影写实风格，低饱和冷青色，右侧窗光贯穿全段；保持主角面容、深色外套、桌面旧信封及房间结构一致。节奏从克制观察逐步转为紧张确认，最后安静收束。禁止 BGM、配乐、歌曲、新增对白和旁白；仅保留室内风声、纸张摩擦、脚步与木门轻响，音效不得遮盖原旁白。

【分时子分镜】
0–3s 镜头1：中远景，平视固定机位，主角位于画面左侧，桌面信封在右前景；主角停顿后缓慢看向信封。镜头极慢推近，焦点从前景信封转到主角眼睛。窗帘投影轻微移动。音效：0.5s右后方微弱风声，2.2s衣料轻响。镜尾以主角视线落点做视线匹配剪辑。
3–6s 镜头2：切到信封俯拍特写，构图方向与上一镜视线一致；手从左侧进入画面，指尖先停顿再触碰纸面。镜头轻微下压并跟随手指，景深变浅。音效：4.4s近距离纸张摩擦，位置居中偏左。5.8s手掌遮满画面，以遮挡转场进入下一镜。
6–10s 镜头3：遮挡退开后切为主角侧脸近景，仍在原房间和同一窗光方向；主角拿起信封，呼吸变急，眉眼从迟疑转为警觉。镜头沿右侧小幅环绕并缓慢推近。音效：6.2s衣袖摩擦，8.0s远处木地板一次轻响。镜尾主角突然转头，利用动作匹配切镜。
10–13s 镜头4：过肩中景，镜头随转头方向快速但平稳地甩向半开的门；门缝光线略微扩大，场景结构不变。先快后慢推向门缝。音效：10.3s短促脚步从右后方传来，12.0s门轴轻响。镜尾让门框掠过镜头形成自然擦镜。
13–15s 镜头5：擦镜后回到主角正面近景，主角握紧信封并屏住呼吸，最终视线定在画外右侧；镜头停止移动，保留最后0.5秒稳定画面供剪辑。窗光略暗但方向不变。音效：13.4s信封被握紧的纸声，随后所有环境音自然减弱。

【负面约束】禁止 BGM、配乐、歌曲、旋律、新增对白、新增旁白；禁止人物、服装、信封、门和房间结构变化；禁止跳轴、无动机乱切、瞬移、动作跳帧、镜头剧烈抖动、字幕、水印与Logo。
```

提交前逐条核对时间覆盖与实图一致性。提示词摘要至少向用户展示全局风格、子分镜数量与时间切分、主要切换方式、动作主线和音效设计，不能只展示一句整体描述。

### 6. 创建并生成视频

每镜创建一个 `video` 节点：

- `prompt`：上一步根据实图写出的中文提示词；
- `duration`：对应的 `5/10/15` 秒槽位；
- `aspectRatio`：与图片一致；
- `workflowId`：从 `GetCanvasCapabilities` 返回的图生视频选项中选择；
- `firstFrameNodeId`：对应 image 节点 ID。

连接 `image → video`，先向用户展示生成摘要并询问“是否开始生成视频？”。等待用户明确确认后，才可调用 `InvokeNodeAction(generate)`。ComfyUI 并发完成顺序可能与镜头号不同；始终按节点 ID 和 `sourcePath` 对齐，不要依赖生成先后顺序。等待所有节点离开 `generating` 状态，再启动新的独立子 Agent；该子 Agent 必须逐段调用 `ReviewStoryboardVideo`，每次只传对应 shot 节点 ID，由工具自动解析 video、提示词、参考图和媒体路径。工具以 Markdown 纯文本返回九维分数、时间戳证据、问题和建议，不返回结构化数据，不计算总分或重做结论；生产 Agent 根据旁白对齐的重要性、问题可见度、修复成本和用户要求决定接受、修改提示词或重新生成。重做仍须再次取得用户授权，并由新的独立子 Agent 复审。

### 7. 逐段变速并创建剪映草稿

调用或遵循 `aigc-canvas:jianying-draft` Skill，使用 pyJianYingDraft 完成合成：

- 按镜头号读取每个 video 的 `sourcePath` 和 shot.scene 中的时间参数。
- 将每段视频放到对应 SRT 开始时间，目标持续时长设为该镜 `narrationDuration`。
- 使用完整视频槽位作为源区间，播放速度设为 `slotDuration / narrationDuration`，让画面精确覆盖该段旁白。
- 旁白音频从时间轴 0 秒开始、保持原速，不做整体拉伸。
- 不添加任何 BGM 或音乐轨。若生成视频自带合格的环境音/拟音，则保留其片段原声并控制音量，确保原速旁白始终清晰；若音轨含 BGM、新增对白或旁白，先静音/移除该片段原声，不能把违规声音带入草稿。
- 直接导入原 SRT 作为字幕轨，不重写字幕时间。
- 草稿分辨率与用户选择的画幅一致。
- 实际运行生成脚本。生产主 Agent 只收集草稿路径、脚本输出和轨道信息，不自行判断草稿是否合格。只有当前系统和剪映版本支持自动导出时才自动导出，否则明确提示用户打开草稿后手动导出。

草稿生成后，把上一步收集的证据交给一个新启动的独立子 Agent，执行一轮新的最终验收；核对实际草稿/脚本输出、视频轨、原速旁白轨、字幕轨、逐段时间位置和总结束时间。只有其报告全部通过，才可宣布完成；若修复草稿，则修复后另启新的独立子 Agent 复审。

## 画布规范

- 画布节点是分镜的唯一数据源，不创建 `.storyboard.json` 或分镜表产物。
- 同一镜从左到右排列为 `shot → image → video`，不同镜头纵向排列。
- 需要查找节点 ID 时调用 `GetCanvasOverview`；修改或检查具体节点时用 `GetCanvasNode` 读取完整数据。写入采用最后写入者生效，不传版本号。
- 优先批量创建和批量连接；生成后由生产主 Agent 收集各节点状态、节点 ID、`sourcePath` 和实际媒体路径，再交给新的独立子 Agent 逐个核验。

## 完成判据

- 以下判据必须由最新启动的独立子 Agent 根据实际产物验证，不能由生产主 Agent 自行勾选。
- shot、合格图片和成功视频的数量一致，并等于分镜数。
- 成片时间轴结束位置与 SRT 最后一句结束时间一致，允许的误差不超过一帧。
- 每段字幕、原速旁白和对应画面时间对齐。
- 剪映草稿已保存，并包含视频轨、旁白轨和字幕轨。
